# Verification and test scripts

> **Scope:** Browser smoke tests, journal touch tests, Android on-device checks and what has/has not been verified.
>
> **Read when:** you run or change `scripts/smoke.mjs`, `scripts/check-journal.mjs` or need the pre-release checklist.
>
> **Related:** setup-build.md, known-gaps.md, ../android/BUILD_APK.md

The guided tour is covered by `scripts/smoke.mjs`: all 16 pages in order (the Notifications step shows its five previews and expands Settings > Notifications in the live journal), the journal's response on each page (Statistics, Settings, Day overview, Period), the widget-only step with its 18 default shortcuts, the Large widget's content, the language switch, offline reloads, the supplied salt drawing, gestures, and the native payload (intake, burned, macros, percentages and BMR).

For repeatable web checks, prepare Android assets, run `npm run build`, install Chromium with `npx playwright install chromium` (on minimal Linux systems use `--with-deps`), then run `node scripts/smoke.mjs`. The script checks all 18 default icon-only shortcuts, the header wordmark with its bundled font, the favicon, the launcher PNG sizes, the exact three salt paths, responsive touch targets, offline persistence, clean native assets, swipes and a simulated native action/snapshot/Back protocol. The simulation is not a device test.

**Historical record (upstream authoring session, not reproducible from this repository because the ZIP is not tracked):** The prepared source ZIP was extracted separately and built with JDK 21 and SDK 36, without installing npm packages in the extraction. Debug, unsigned release, and the Android instrumentation-test APK compiled; the release vital-lint check passed. The current manifest registers four widget providers. No signed production APK or keystore is distributed. Physical launcher behavior, real system gestures, camera, document picker and background scheduling remain device checks in [the Android guide](../android/BUILD_APK.md).

**Prerequisite not declared in `package.json`:** both test scripts `import { chromium } from 'playwright'`, but `playwright` is not a dependency. Install it first (`npm i -D playwright && npx playwright install chromium`) or run them with `npx -p playwright`. `scripts/smoke-entry.tsx` and the committed `scripts/smoke.bundle.js` are an older jsdom harness that `smoke.mjs` no longer references.

## Page change benchmark

`scripts/bench-page-change.mjs` (needs `playwright` and its Chromium system libraries) seeds a large journal (500 logged days, 60 meals, 30 recipes, 14 photos), throttles the CPU 4x (`KC_THROTTLE=1` for none) and taps Today -> every other page -> Today three times, printing the longest main-thread block and the longest frame of each change. Compare before / after a change on the same machine; a long task above ~100 ms is felt as a freeze. Reference numbers and the reasoning are in [performance.md](performance.md).

It runs **two scenarios** (`KC_SCENARIO=collapsed|open|both`, default both): `collapsed` (a fresh install, everything closed) and `open` (the real-world case: Meals, Recipes, Meal diary, Meal planner and Photo diary open, 5 meal and 5 recipe cards expanded). **Budget:** the longest main-thread block of Today -> Custom must stay below `KC_BUDGET_MS` (default 250 ms) at the default 4x throttle in every scenario, otherwise the script prints the offenders and exits with code 1, so it can be used as a CI gate (CI needs a runner that can start Chromium). The budget is not enforced when `KC_THROTTLE` is below 4.

Regression tests that need no browser: `tests/page-change.test.tsx` (a settings-only consumer of the four text hooks is not re-rendered by a tab change or a dialog, `LazyBody defer`, photo lookups, `planGroupViews` against the old implementation, `playPageChange` returning both animations, `afterPaint`).

## Meal card fit check

`node scripts/measure-meal-card.mjs` (after `npm run build`; needs `playwright` and Chromium's system libraries) prints, for 390 and 320 px viewports, the last card width at which the calorie figure (Normal and Compact) and the note / photo icons (Compact) still fit, and the container max-width to put in `src/styles/performance.css`. Re-run it when the card's padding, icons, fonts or the pills change. By hand: Today in Normal, Compact and Expanded at 320 and 390 px, light and dark; in the advanced layout resize a meal field down: the figure disappears first, **+** and the arrow stay, nothing is clipped; note / photo icons show when a Compact card is wide (>= 210 px, e.g. an open one or a tablet) and disappear when it is tight. In DevTools > Performance, Custom -> Today shows one large Layout at the entry, not several interleaved with the React commit.

## Page transition check

`scripts/check-page-transition.mjs` (needs `playwright` like the other scripts) loads the production `dist/` at 390x844 with touch and records one sample per animation frame while the page changes by tap, Back and the food catalogue. It fails on: a frame with nothing drawn, two pages both clearly visible, horizontal overflow, more than one document-height change per page change (a leftover old page stretching the document), a page left behind, running animations, rail / page `transform` or `style` left over, `kc-page-moving` left on `<html>`, a wrong scroll position, a tap lost during a transition, rapid taps ending on the wrong page, a second page or a fade under reduced motion, and page errors. `KC_REPORT_ONLY=1` prints the metrics without asserting (used to compare with the previous build); `KC_VIEWPORT=1280x800` runs it with the desktop layout. Known pre-existing failure, unrelated: `check-journal.mjs` stops after its second block at the Settings step (`Track sugar intake` button no longer exists); the swipe and sheet blocks before it pass.

## Search and dialog check

`scripts/check-search-and-dialog.mjs` (needs `playwright`; run after `npm run build`) loads the production `dist/` at 390x844 with touch and fails on: the 12 MB catalogue being requested before two characters are typed in Add food, no catalogue search worker running after typing, no catalogue results for "nutella", a main-thread task longer than `KC_LONGTASK_MS` (default 200) while typing, a closing dialog that is not the same element that was open / is not `inert` / loses the typed text / is ever joined by a second overlay (a clone), anything left behind after the exit (overlay, host children, running animations), a dialog that does not open again right away, and page errors. `KC_THROTTLE=4` throttles the CPU. Unit tests for the same round: `tests/fuzzy.test.ts` (new search vs a verbatim copy of the old one), `tests/catalogueSearch.test.tsx` (worker protocol, cache, fallback, hook), `tests/dialogExit.test.tsx` (both ways React removes a dialog, under `StrictMode`). Details: [search-and-animation-performance.md](search-and-animation-performance.md).

## Required checks (CI)

`.github/workflows/ci.yml` runs `npm run typecheck`, `npm run lint`, `npm test`, `vite build` (and checks the stamped worker) and `node scripts/check-widget-layouts.mjs`. `npm run check` runs the same locally. The Vitest suite in `tests/` covers the Android export path (`backup-android.test.tsx`), food logging, navigation, settings saving, backup export / import (backup version 2 without pictures, picture notes, old 1.2 files, refusal of newer files: `tests/backup.test.tsx`, `tests/backup-ui.test.tsx` for the pictures warning), the IndexedDB day store and its migration, the write queue, photo blobs, midnight scheduling and widget dates, plus (plans round) the recent-food chips, plan grouping, the shopping-list maths, journal normalising and the planner wizard (name on page 1, reuse, whole-plan edit): `tests/plans-shopping.test.tsx`, `tests/planner-wizard.test.tsx`. Browser scripts (`npm run test:browser`) stay manual.

**Android export fix round 3 (false failure on Downloads):** `ExportStoreTest` now has 20 Robolectric tests (the SIZE column reporting 0 for a complete file, a provider serving half the bytes, `wt` refused then `w`, no read-back allowed, a non-empty document never deleted). **They were written without an Android SDK / JDK in the authoring sandbox: not compiled and not run.** Run `cd android && ./gradlew :app:testDebugUnitTest` first. **Device acceptance (manual):** export JSON, Excel and pictures to Downloads, Drive and a custom folder: each file non-zero, the size shown, no leftovers; the JS test `tests/backup-android.test.tsx` mocks the plugin and cannot catch this class of bug.

**Android export fix round 2 (0 B files):** the Java is now covered: `ExportStoreTest` (Robolectric, 16 tests: copy loop against a stub `ContentProvider`, recovery after process death) runs with `cd android && ./gradlew :app:testDebugUnitTest` (after `npx cap sync android`; JDK 21 and about 1.5 GB of free memory). `tests/backup-android.test.tsx` covers JSON, Excel and pictures (cancel, bytes, errors, recovered exports). **Device acceptance (still manual):** (1) export JSON, Excel and pictures to Downloads and to Drive: every file non-zero and `... (<size>)` shown; (2) close the picker: nothing shown; (3) force a failure (for example revoke storage access of the provider, or pick a read-only folder): red error, no 0 B file; (4) background the app while the picker is open, then save: file non-zero; (5) swipe the app away or force-stop it while the picker is open (`adb shell am kill com.kcalsync.app` is enough), save, reopen: the file is written and Settings > Data Backup says `Saved after the app restarted`, or the empty document is gone; (6) `adb logcat -s KakcalExport` shows the real exception for any failure.

**Earlier, Android export fix round (round 1, superseded):** verified by `tsc`, lint, `npm test` (new `tests/backup-android.test.tsx`: the APK path with the plugin mocked). The Java change in `JournalDevicePlugin.java` could not be compiled or run in the authoring sandbox (no Android SDK): build the APK and run the device check in [../android/BUILD_APK.md](../android/BUILD_APK.md) (step 6: the exported file must not be 0 B).
