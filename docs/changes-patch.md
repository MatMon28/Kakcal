Apply from that repository revision (the base commit above):

```sh
git apply --check changes.patch   # dry run
git apply --index changes.patch   # apply and stage (binary files included)
npm ci
npm run build
```

Use `git apply --3way changes.patch` against a repository that has moved on. The patch never contains `node_modules/`, `dist/`, Gradle outputs or files generated by `cap sync`, and it does not include itself.

**Creating one** (from the repository root, after your edits):

```sh
git add -A -- . ':!changes.patch'
git diff --cached --binary HEAD > changes.patch
git reset -q                     # leave the working tree as it was
```

When you add a feature or a file, update the matching document first (see the maintenance table in [README.md](README.md#keeping-the-docs-current)), then regenerate the patch and update the base commit above.
