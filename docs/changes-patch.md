Apply from that repository revision:

```sh
git apply --check changes.patch   # dry run
git apply --index changes.patch   # apply and stage (binary files included)
npm ci
npm run build
```

Use `git apply --3way changes.patch` against a repository that has moved on. The patch never contains `node_modules/`, `dist/`, Gradle outputs or files generated by `cap sync`, and it does not include itself. No package, config, permission, Android or data change, and no new remote API. Behaviour change: none visible; collapsed Custom card bodies exist in the DOM only after the first time they are opened.

**Creating one** (from the repository root, after your edits):

```sh
git add -A -- . ':!changes.patch'
git diff --cached --binary HEAD > changes.patch
git reset -q                     # leave the working tree as it was
```

When you add a feature or a file, update the matching document first (see the maintenance table in [README.md](README.md#keeping-the-docs-current)), then regenerate the patch and update the base commit above. When a round is finished, move its paragraph from the top of this file to [changes-patch-history.md](changes-patch-history.md) so this file stays short.
