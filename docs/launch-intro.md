# Launch intro

> **Scope:** The six one-phase launch animations, random pick, theme awareness, where it runs, URL switches and files.
>
> **Read when:** you touch `src/components/intro/` or `src/assets/kakcalculator_intro/`.
>
> **Related:** motion.md, file-map/android-native.md, ../src/assets/kakcalculator_intro/intro_animation.md (animation source spec)

When the app opens it plays one of the **six one-phase launch animations** in `src/assets/kakcalculator_intro/` (`animations/01..06-*.svg`, documented in `intro_animation.md`): Soft-serve, Stack & plop, Jelly key-press, Iris flip, Swirl & unfold and Flush & return. They are generated (`scripts/generate-intro-animations.mjs`, definitions in `scripts/brand-animations.mjs`) from the solid poop with the carved K, see [brand.md](brand.md#animations). Each runs 2.0 to 2.4 s in its SVG file and is played **2.5x faster** (`INTRO_SPEED`), so about 0.80 to 0.96 s, the same length as the previous set (0.79 to 0.95 s), ending exactly on the brand icon.

- **A different animation every launch.** `pickIntroAnimation()` chooses at random but never the animation of the previous launch (remembered in `localStorage` key `kcalsync_intro_last`). The choice is made once per page load.
- **Starts as early as possible.** `main.tsx` imports `intro/earlyStart.ts` *before* `./App`; ES modules run in import order, so `startLaunchIntro()` (in `launchIntro.ts`, plain DOM) inserts the overlay and removes the `#kc-boot` layer *before* the app modules are evaluated and before React exists. `main.tsx` then awaits `afterFirstPaint()` (a frame + timeout, 150 ms fallback for hidden tabs) before the first `createRoot().render`, so the heavy first render can never delay the animation's first frame. The plain background-colour screen therefore lasts only until the bundle is parsed (about 100 ms for the 1 MB inlined `dist/index.html` in headless Chromium, measured as overlay-in-DOM time; on a phone it scales with CPU). `#kc-boot` is removed instantly (not faded) because the overlay is the same plain colour.
- **Runs to the end, never interrupted.** The journal mounts underneath the overlay, so nothing waits for the animation, but loading finishing no longer cuts the animation short. The overlay leaves only when **both** (a) the animation has played to its last frame (`duration + HOLD_MS` 120 ms, timed from the first painted frame) **and** (b) `useAppReady()` (first screen committed + fonts loaded + two frames painted) has reported through `IntroSplash` -> `markAppReady()`. It then fades in 200 ms (`FADE_MS`). If the app is slower than the animation the finished icon stays until it is ready (safety cap: `MAX_EXTRA_WAIT_MS` 3 s after the animation). Tap anywhere to skip (120 ms fade, `SKIP_FADE_MS`). Typical total overlay time is about 1.1 to 1.3 s.
- **Speed.** `INTRO_SPEED = 2.5` in `introAnimations.ts` (the new animations are about 2.2 s long, so they need 2.5x to take as long as the previous set did at 1.35x). The SVGs contain only animation durations (`NNNms`, no delays), so at load every `NNNms` in the embedded CSS is divided by the factor; keyframe percentages and the final frame are unchanged. Change one constant to make it faster or slower.
- **Theme-aware, transparent card.** The SVG is inlined (so CSS variables resolve) and the overlay uses the app's `--bg`. The icon's rounded "card" (the `--kc-cream` token) is the page background itself in **every** theme (`.kc-intro { --kc-cream: var(--bg) }` in `intro.css`; it used to be cream in Light, which showed as a lighter box on the beige background), so only the K and the poop are visible and no box shows. `--kc-ink` is `#0B0F1E` in Light and `#F9F3E6` in Lite Dark / Dark (Koink's colours) (section 3 of `intro_animation.md`). The generator paints the animations with `var(--kc-cream, #F9F3E6)` and `var(--kc-ink, #0B0F1E)`; the inverted start of Iris flip and the vortex rings of Flush & return use the same two tokens and are gone before the last frame.
- **Where it runs.** Android, `?view=app` and the browser tour's top-level page. It never runs inside the tour's iframes (the live journal and widget gallery), with `?tour=1`, or when `prefers-reduced-motion` is set.
- **URL switches (review only).** `?intro=0` skips it; `?intro=1` to `?intro=6` forces one animation, e.g. `index.html?view=app&intro=4`.

Files: `src/components/intro/introAnimations.ts` (the six imported SVGs with sped-up durations, the picker and `shouldShowIntro`), `launchIntro.ts` (overlay creation, timing, skip, `afterFirstPaint`), `earlyStart.ts` (side-effect import that starts it first), `IntroSplash.tsx` (React bridge, renders nothing: reports `ready`, learns when the overlay is gone), `useAppReady.ts` (the loading-finished signal) and `intro.css` (overlay, tokens, fade). `App.tsx` renders `<IntroSplash ready onDone />` next to the journal or tour.

## Only the animation: no logo and no colour jumps

The app used to show the full-name wordmark on a Light cream launch screen, then a cream WebView, then the themed boot screen: three different pages before the animation for Dark users. Now every surface that is visible before the animation is a **plain background colour equal to the current `--bg`**, so the first thing that appears is the animation itself:

1. **Android system launch screen.** It cannot be removed on Android 12+, so it is a transparent icon (`res/drawable/splash_blank.xml`, keep it explicit: with no icon Android falls back to the launcher icon) on the app background. The colour cannot be set at run time, so `scripts/generate-splash-themes.mjs` generates one tiny style per possible `--bg` (`Splash_<hex>` in `res/values/splash_themes.xml`: 6 presets x 3 modes + 10 mono hues x 3 modes = 48) and `LaunchBackground.java` activates the right one with `Context.setSplashScreenTheme` (**Android 13+**, applies from the next cold start). On Android 12 and older the launch screen stays the Light cream of `AppTheme.NoActionBarLaunch` (no platform API); known gap 7.
2. **Window and WebView.** `MainActivity` sets the window background and the WebView background to the saved colour before the page loads (this was the cream frame after the launch screen).
3. **Web boot layer.** `index.html` `#kc-boot` is a full-screen layer in `--bg` with no logo. It fades out over the already-rendered intro (`dismissBootSplash()`), so the cross-fade is invisible.

How the colour reaches native code: `applyThemeAttributes` runs on every theme / style / hue change and on start; `AppContext.tsx` then calls `syncLaunchBackground(--bg)` (`src/utils/android.ts`) which calls the `JournalDevice.setLaunchBackground` plugin method; `LaunchBackground.save` stores it in the `launch_background` SharedPreferences and switches the splash style. The very first launch after installing has no stored colour yet and uses the Light fallback.

Re-run `node scripts/generate-splash-themes.mjs` when a `--bg` in `src/index.css` (rules in `src/styles/*.css`, see [file-organisation.md](file-organisation.md)) or the mono palette in `src/utils/themes.ts` changes. `scripts/outline-wordmark.mjs` now only writes the logo into `index.html` / `splash_wordmark.xml` with `--launch-screens` (not used).

## First launch only

The animation plays to its last frame **only on the first launch on a device** (`kcalsync_intro_seen` in localStorage, set when the overlay leaves). Later launches (`isReturningLaunch()`) leave as soon as the app is ready, with the quick fade, and a tap still skips. `?intro=1`..`?intro=6` always plays in full. The earlier statement that it "always plays to its last frame" applies to the first launch only. Code: `introAnimations.ts`, `launchIntro.ts`.
