# Known gaps between documentation and repository

> **Scope:** things found during the documentation audit that the code or `package.json` does not (yet) do. Documents describe the repository as it **is**; this file lists what is missing or surprising.
>
> **Read when:** a documented command fails, or you plan housekeeping.
>
> **Related:** [setup-build.md](setup-build.md), [verification.md](verification.md), [provenance.md](provenance.md)

**Advanced personalisation round:** verified by `tsc`, `npm run build` and a jsdom run of the built bundle (goal icons, tab order, Body cards, dock buttons, pop-up). Visual layout (icon sizes in each of the 7 themes, charts) was **not** checked in a real browser or on a device. The guided tour does not mention the Body page (it is opt-in and off by default).

**Search and animation performance round:** verified by `tsc`, lint, `npm test` (new `fuzzy`, `catalogueSearch`, `dialogExit` suites), `npm run build` and `scripts/check-search-and-dialog.mjs` in desktop headless Chromium (390x844 touch viewport, CPU throttled 1x / 4x / 6x). **Not** verified on a real phone or in the Android WebView / Safari: the catalogue Web Worker (module worker; browsers without module-worker support fall back to searching on the main thread) and the dialog exit through the host's `removeChild` override. The `flushSync` calls in `PageSwiper.tsx` were not profiled and are unchanged. While the food database page or a barcode lookup is open, two copies of the 12 MB catalogue exist in memory (main thread and worker). See [search-and-animation-performance.md](search-and-animation-performance.md).
