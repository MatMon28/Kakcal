# Build the Kakcal APK

This project contains the offline journal, four native Android home-screen widgets (Small, Extra-small, Medium, Large) and optional reminder notifications. The launcher uses Android `RemoteViews`, not a web page. No backend, Firebase account, API keys or running development server are required.

> Short overview and the doc index: [../docs/android-apk.md](../docs/android-apk.md), [../docs/README.md](../docs/README.md). The prepared ZIP below is optional and **not tracked in git**: create it with `python3 scripts/package-android.py` (after `node scripts/prepare-android.mjs`).

## Open the prepared download (only if you generated the ZIP)

1. Select **Android project** in the guided web tour (top right). Extract the entire `Kakcalculator-Android-Studio.zip`; keep its folders together.
2. Install Android Studio Otter (2025.2.1) or newer with Android Gradle Plugin **8.13.0** support. In SDK Manager install **Android SDK Platform 36**, **Build Tools 35.0.0**, and Platform-Tools. Review and accept the SDK licenses on your own machine.
3. In Studio, **Open** the extracted **`Kakcalculator/android/`** folder containing `settings.gradle`, not the outer folder or just `app/`. Do not create a new project or run `cap add`.
4. In **Settings > Build, Execution, Deployment > Build Tools > Gradle**, set the Gradle JDK to **21** and use the included **Gradle 8.14.3 wrapper**. Let Gradle sync finish. The first build needs internet for SDK/Gradle/Maven dependencies; the installed app does not.
5. Select the **app** configuration and Run on Android 7.0+ (API 24+) with an updated Android System WebView. Open the app once. Long-press the home screen, open the launcher's Widgets picker and look for Kakcalculator.

The download includes clean compiled web assets, Capacitor configuration, the generated Cordova compatibility module, the wrapper JAR, and the three native Gradle modules under `node_modules/@capacitor/` (android, app, local-notifications). **You do not need Node/npm to build this prepared archive in Studio.** It does not include a private keystore or the full JavaScript toolchain.

## After editing the web app

From the project root, one level above `android/`, use Node.js **22 or newer**:

```sh
npm ci
node scripts/check-widget-layouts.mjs
node scripts/prepare-android.mjs
npx cap open android
```

Use the same steps for a fresh source checkout. The cross-platform preparation script disables all demo seeds, selects the standalone journal, and builds local JS, CSS, fonts, catalogs and licenses. It runs `cap sync android` and verifies the copied HTML and plugin list. The source download and browser service worker are excluded from the APK. **A plain `npm run build` produces the browser preview**, not the clean Android release bundle. Do not overwrite the prepared assets with that build. Native Java/XML edits need only a Gradle rebuild. The launcher PNGs and the Play Store icon come from `src/assets/brand/kakcalculator-icon.svg`; after changing that artwork, run `node scripts/render-brand.mjs` (this needs `npm ci` and `npx playwright install chromium`).

If a Capacitor Gradle project is missing, extract the entire ZIP or run the source commands above. If the SDK is missing, select its location in Studio. Do not share machine-specific `local.properties`.

### Gradle resolves Capacitor from `node_modules/`

`settings.gradle` applies the generated `capacitor.settings.gradle`, which maps `:capacitor-android` to `../node_modules/@capacitor/android/capacitor` `:capacitor-app` to `../node_modules/@capacitor/app/android` and `:capacitor-local-notifications` to `../node_modules/@capacitor/local-notifications/android` (reminder notifications). The `:capacitor-cordova-android-plugins` module is generated by `cap sync` and is git-ignored. **Therefore `npm install` and `npx cap sync android` must run in the project root (one level above `android/`) before this folder is opened or built.** From a source checkout the single command is:

```sh
npm install
node scripts/prepare-android.mjs   # clean no-demo web build + npx cap sync android + checks
cd android && ./gradlew assembleDebug   # Windows: gradlew.bat assembleDebug
```

> `npm run android:prepare` exists in `package.json` but currently only runs `npm run build && npx cap sync android` (browser preview, **not** the clean no-demo bundle). Use the commands above; see [../docs/known-gaps.md](../docs/known-gaps.md).

If those directories are missing, Gradle would normally create empty placeholder projects and fail later with `No matching variant of project :capacitor-android was found` / `No variants exist`. The pre-flight guard at the top of `settings.gradle` now stops the build (and the Studio Gradle sync) immediately with a message that names the missing directory and the command to run. After running it, choose **File > Sync Project with Gradle Files**. The prepared ZIP already contains `node_modules/@capacitor/` and the generated module, so it passes the guard without npm.

## Build and sign

**Debug:** choose **Build > Generate App Bundles or APKs > Generate APKs** (the menu name varies by Studio version). Output: `android/app/build/outputs/apk/debug/app-debug.apk`. Alternatively, from `android/`, run `./gradlew assembleDebug` or `gradlew.bat assembleDebug` on Windows. Use `chmod +x gradlew` if extraction dropped its Unix executable bit.

**Release builds are shrunk:** the `release` type uses R8 (`minifyEnabled true`) and `shrinkResources true`, and ships `src/main/baseline-prof.txt`; resources read by name are protected in `res/raw/keep.xml` (see [Startup performance](../docs/startup-performance.md)). Test the *release* variant on a device after changing native code or adding a `getIdentifier` lookup. **Release:** choose **Build > Generate Signed App Bundle / APK**, select APK, the `app` module and the `release` variant. Create or select **your own keystore**. Studio shows the chosen output directory after the build. For Google Play, select Android App Bundle instead. Keep keys and passwords outside source control; a debug signature is not a production signing identity.

**Identity:** `com.kcalsync.app`, `versionCode 3`, `versionName 1.1.0`, `minSdk 24`, `compileSdk/targetSdk 36`. Before publishing, make sure the version code exceeds your last distributed build. Change it in `app/build.gradle` if needed. Updating an install requires the same application ID and signing key. A no-demo build does not erase older test data. Export a backup before clearing app storage or uninstalling.

## Widget behavior

| Widget | Contents |
| --- | --- |
| Small | Food, Movement, Water, Poop and Weight: five circular icon buttons. |
| Extra-small | Food, Water and Poop: three circular icon buttons. |
| Medium | Default size **4x2** (`minHeight`/`minResizeHeight` 110 dp, `targetCellHeight` 2). Carbs, protein and fat in grams on a row as tall as the buttons (40 dp), the five 40 dp icon buttons, and the intake and burned cards (one line each, no progress bars) filling all the remaining height. |
| Large | Intake and burned cards with their icons, badge and progress bar; carbs, protein and fat with grams and percentages; and five icon buttons. Same arrangement as Ultra minimal Today, with no logo, name or "today" label. |

The translucent tray behind the Small and Extra-small buttons follows the buttons' shape in every theme style (pill, rounded rectangle or chamfered).

An optional sixth **Custom** button can be added to Small, Medium and Large (Settings > Custom buttons). Details: [../docs/widgets.md](../docs/widgets.md).

There are no action captions. Accessibility descriptions and picker labels are available in English and Italian. Size hints are advisory; the launcher controls its grid, long-press, positioning and resizing. A tap opens the existing app dialog on **the current local day**; no entry is committed until you save.

`MainActivity.java` registers the local plugin and retains an allowlisted action across cold launch and activity recreation. A warm launch reuses the activity via `singleTask` and `onNewIntent`. React subscribes before taking the pending action once. The buttons use explicit immutable `PendingIntent`s with distinct request codes.

The journal is the source of truth. The native widget cache contains only language and dated nutrition totals, not names, notes, weight or cycle logs. Yesterday (for timezone shifts), today and already-logged future dates are mirrored. The renderer selects the current local date, with zero for missing days. Edits and imports refresh the cache. The large widget also refreshes on launcher updates, resizing, boot, time/date changes, and an inexact non-waking midnight alarm. Android may defer refresh when asleep or in Doze. The widgets use no exact alarm and no background network service (the reminder notifications declare `SCHEDULE_EXACT_ALARM` separately, see [../docs/notifications.md](../docs/notifications.md)).

## Offline operation

Capacitor serves `assets/public/index.html` internally at a local HTTPS origin. Leave `server.url` unset. The app and launcher widgets need no internet for ordinary use, including first launch. Known/saved barcodes resolve locally. Only an explicit unknown-barcode lookup queries Open Food Facts over HTTPS, with a timeout and offline/manual fallback; following an external source link also needs internet.

Camera access is optional and scanner support varies by WebView. `INTERNET` permits remote barcode lookups, `RECEIVE_BOOT_COMPLETED` restores widget refresh scheduling and reminder alarms, `POST_NOTIFICATIONS` and `SCHEDULE_EXACT_ALARM` serve the reminder notifications, and `CAMERA` is requested only for barcode scanning. There is no account, telemetry or cloud-sync service. Android automatic backup is disabled. **Settings > Data Backup** exports unencrypted private JSON through Android's document picker without broad storage permission. Browser and installed-app data are separate; use export/import to transfer a journal.

## Device checks before distributing

1. On a fresh install, enable airplane mode **before the first launch**. Verify that the journal is empty. Log food, water, activity, poop and weight, close and reopen, and check persistence.
2. Add the four widgets (Small, Extra-small, Medium, Large). Test every shortcut with the app closed, backgrounded, on a previous date, and already in a dialog. Confirm cancel makes no entry and Save logs once, for today.
3. Edit/remove a food, export a backup (*Export JSON*; the saved file must not be 0 B, the message shows its size) and import it. Compare the large widget with Today. Check resizing, midnight, timezone changes, reboot, large font settings and TalkBack on your actual launcher.
4. Turn on **Settings > Ultra minimal** and check the outlined diamond salt symbol. Swipe horizontally on content. Vertical scrolls, editable fields, horizontal lists, pinch gestures and system-edge Back should not change tabs. Check portrait/landscape, the keyboard and gesture/three-button navigation.
5. Use Back in nested dialogs, the Today calendar, Browse Foods, and a non-Today tab. It should dismiss the top overlay, return from the catalog, then return to Today. Back at the root backgrounds the app.
6. Export to a local JSON document, cancel and repeat (cancelling must show no "saved" message), then import the saved file. **Check the saved file is not 0 B** (open it in a file manager; the message shows its size): do it for *Export JSON*, *Export to Excel* and *Export meal pictures*, saving to Downloads and, if you use it, Google Drive. Deny camera permission and check manual barcode entry; try known and unknown codes while offline.
7. With a device attached, run `./gradlew connectedDebugAndroidTest` from `android/` to check provider registration and accepted intent actions. Build and test your own signed release, including an update signed with the same key.


### Reminder notifications on a device

Settings > Notifications uses `@capacitor/local-notifications`. Device checklist: on Android 13+ the first switch asks for the notification permission; use **Send a test notification** to confirm delivery; reminders keep firing with the app closed and after a reboot; on Android 12+ grant *Alarms & reminders* to the app for on-the-minute delivery (otherwise the plugin schedules inexact alarms); tapping a reminder opens the matching screen. Battery-saver modes of some manufacturers can delay alarms for apps that are not exempt from battery optimisation.
