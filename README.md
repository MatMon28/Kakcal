# Kakcalculator

A local-first nutrition, activity and wellness journal built with React 19, TypeScript, Vite and Tailwind CSS v4. The browser opens a guided tour of every page, with the widgets last; Android has a bundled Capacitor app, four native home-screen widgets and optional reminder [notifications](#notifications). There is no account or application backend.

## Setup & Build

> **Before you open or build `android/`, run `npm install` and `npx cap sync android` in the project root.** The Android project is not self-contained: Gradle resolves the Capacitor native modules straight out of the root `node_modules/` directory, and `cap sync` generates git-ignored files that Gradle also needs.

**Requirements:** Node.js **22 or newer**, JDK **21**, Android SDK Platform **36**, Build Tools **35.0.0**. Android Studio Otter (2025.2.1) or newer with AGP 8.13.0 support; the included wrapper pins Gradle 8.14.3.

**One command (fresh clone, after transferring the folder, or whenever the Android build misbehaves):**

```sh
npm run android:prepare      # npm install + clean no-demo web build + npx cap sync android + checks
```

Then open `android/` in Android Studio (`npm run android:open`), or build an APK directly:

```sh
npm run android:build        # macOS/Linux: android:prepare, then  cd android && ./gradlew assembleDebug
npm run android:build:win    # Windows:     android:prepare, then  cd android && gradlew.bat assembleDebug
```

The debug APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`.

| Script | What it does |
| --- | --- |
| `npm run android:prepare` | `npm install`, `node scripts/check-widget-layouts.mjs`, then `node scripts/prepare-android.mjs`: the clean no-demo production web build (the offline food catalogue `dist/data/off-foods.bin` is copied too), `npx cap sync android` (copies `dist/` into the APK assets, regenerates `android/capacitor-cordova-android-plugins/`, `capacitor.settings.gradle` and the plugin list) and integrity checks. |
| `npm run android:sync` | `npx cap sync android` only. Use it after native plugin changes when `dist/` is already a clean Android build. |
| `npm run android:build` / `android:build:win` | `android:prepare` followed by `./gradlew assembleDebug` / `gradlew.bat assembleDebug` inside `android/`. |
| `npm run android:open` | `npx cap open android`: opens `android/` in Android Studio. |
| `npm run android:check-widgets` | `node scripts/check-widget-layouts.mjs`: fails if a widget layout uses a view class RemoteViews cannot inflate (a plain `<View>` makes the launcher say "Can't load widget"). Part of `android:prepare`. |
| `npm run build:catalog` | `node scripts/build-off-catalog.mjs`: rebuilds `public/data/off-foods.bin` from the Open Food Facts export (see [Open Food Facts catalogue](#open-food-facts-catalogue)). |

### Why this is required (and how the build protects itself)

`android/capacitor.settings.gradle` (generated by Capacitor) wires the native modules to the **root** `node_modules/`:

| Gradle subproject | Resolved from |
| --- | --- |
| `:capacitor-android` | `../node_modules/@capacitor/android/capacitor` |
| `:capacitor-app` | `../node_modules/@capacitor/app/android` |
| `:capacitor-local-notifications` | `../node_modules/@capacitor/local-notifications/android` |
| `:capacitor-cordova-android-plugins` | `android/capacitor-cordova-android-plugins/` (generated by `cap sync`, git-ignored) |

When `node_modules/` is missing or incomplete (a fresh clone, a copied or zipped folder, an interrupted install, or a OneDrive/Dropbox folder where `node_modules/` is excluded or "online-only"), stock Gradle does **not** complain: it silently creates empty placeholder subprojects with no build variants, and the build fails much later with the cryptic `No matching variant of project :capacitor-android was found` / `No variants exist`.

To prevent that, **`android/settings.gradle` runs a pre-flight guard before any project is included.** It verifies that `../node_modules/@capacitor/android` and `../node_modules/@capacitor/app` contain their Gradle modules and that `android/capacitor-cordova-android-plugins/` has been generated. If anything is missing, Gradle (and the Android Studio sync) fails immediately with a human-readable message that tells you to run `npm install` / `npx cap sync android` (or `npm run android:prepare`) in the project root. A missing web bundle (`android/app/src/main/assets/public/index.html`) only prints a warning, because Gradle can still compile, but the APK would open a blank screen.

**Troubleshooting**

- *"Kakcalculator Android build cannot start: Capacitor native modules were not found"* → run `npm run android:prepare` in the project root, then re-sync Gradle in Android Studio.
- *"android/capacitor-cordova-android-plugins/ has not been generated"* → `npm run android:sync` (or `android:prepare`).
- *`No matching variant of project :capacitor-* was found`* (older checkouts without the guard) → same cause, same fix: `npm run android:prepare`.
- *"The Capacitor CLI requires NodeJS >=22.0.0"* → install Node.js 22 LTS or newer.
- *`Could not find or load main class org.gradle.wrapper.GradleWrapperMain`* → `android/gradle/wrapper/gradle-wrapper.jar` is missing. It is the stock Gradle 8.14.3 wrapper JAR (SHA-256 `7d3a4ac4de1c32b59bc6a4eb8ecb8e612ccd0cf1ae1e99f66902da64df296172`, published at `services.gradle.org/distributions/gradle-8.14.3-wrapper.jar.sha256`); it is also shipped inside `node_modules/@capacitor/cli/assets/android-template.tar.gz`. On macOS/Linux also `chmod +x android/gradlew`.
- `cap sync` is not run automatically by Android Studio. Re-run `npm run android:prepare` after editing the web app or installing/removing a Capacitor plugin. A plain `npm run build` is the **browser preview** (demo seeds, service worker) and should not be synced into the APK.

### Applying `changes.patch`

`changes.patch` in the project root (and copied to `public/changes.patch` for direct download in the web preview) is a `git diff --binary` against GitHub commit **`26c04ec` ("Added notifications")**. Apply it to a checkout of that commit (or one whose files still match it):

```sh
git apply --check changes.patch   # dry run
git apply --index changes.patch   # apply and stage (binary files included)
npm run android:prepare           # node_modules, widget check, web build, cap sync
```

The patch contains the changed source files (this round: the widget icon fix and the launch intro; no dependency changes, so `npm install` is only needed on a fresh checkout); the large catalogue and wrapper JAR are already tracked upstream and unchanged. Use `git apply --3way` against a repository that has moved on. It never contains `node_modules/`, `dist/`, Gradle outputs or files generated by `cap sync`.

## Widgets

| Size | Actions and information |
| --- | --- |
| Small (primary) | Five circular shortcuts: Food, Movement, Water, Poop and Weight, plus an optional sixth **Custom** button. |
| Extra-small | Three circular shortcuts: Food, Water and Poop. |
| Medium | The Large widget's figures in a shorter layout: intake and burned cards (kcal and the balance badge, **no progress bars**, shorter intake/burned cards than the Large widget), carbs, protein and fat in **grams only** (no percentages), and the five shortcuts (plus the optional **Custom** button). |
| Large | Intake and burned cards (kcal, with the balance badge and a progress bar), carbs, protein and fat with a **macro letter in the top-left corner** (C, P, F; G in Italian), grams and share of calories, and the five shortcuts (plus the optional **Custom** button). Same arrangement as Ultra minimal Today. |

**Style and Custom button** (Settings > Appearance > Home-screen widgets, and Settings > Custom buttons): *Light* is the default; *Dark* keeps the translucent background, just darker (all four widgets, with light-on-dark text and tinted cards on the Large and Medium ones). Switching the **app** to Dark also sets the widgets to Dark, and they can still be changed independently. **The widget button style matches the active theme style** (`classic`, `angular`, `aurora`, `pop`, `playful`, `minimal`, `mono`): button geometry (`--dock-btn-radius`, `--clip-sm` chamfered corners in `angular`), borders (`--dock-btn-border`), fills (`--dock-1..6`) and icon inks (`--dock-icon-1..6`) follow the chosen style preset in both the browser widget gallery and the native Android widgets (`themeStyle` and `monoHue` in `publishNutrition`). The *Custom button in widgets* switch adds the sixth custom-tracker button to the **Small, Medium and Large** widgets (not Extra-small); it does what the Today dock's custom button does: it opens the only custom tracker, or the picker when there are several. The choices travel to the launcher in `publishNutrition` (`widgetStyle`, `themeStyle`, `monoHue`, `widgetCustomButton`), the widgets re-render immediately, and the layout of each style is a separate `*_dark` resource because RemoteViews cannot recolour a layout at runtime. The browser tour's widget gallery reads the same settings.

**Icons in non-classic styles.** In every style other than `classic` the native widgets draw each shortcut into a bitmap (`renderStyledActionBitmap` in `JournalWidgetProvider.java`): the style's plate (circle, chamfered, rounded square, border), then the icon glyph tinted with the style's ink colour. The glyph now comes from dedicated plate-less vector drawables (`res/drawable/widget_glyph_{food,movement,water,poop,weight,custom}.xml`, drawn at the same 24 of 48 units as the classic icons and tinted with `Drawable.setTint`). Previously the glyph was cut out of the circular classic icon by colour distance against a sample pixel that lay *outside* the circle, so with any other style the icons came out as solid ink blobs or vanished. The classic `widget_*_icon.xml` drawables (plate + glyph) are unchanged and still used for the `classic` style and as the fallback. When you edit an icon, keep the matching `widget_glyph_*` file in step.

All action buttons are **icon-only** and retain accessible names. The two smaller widgets have a translucent background and no branding or headings. The Large widget has no logo, name or "today" label. Its intake and burned cards use the app's Today colours, icons and badge rules, and the macro cards show grams with their share of calories. The full wordmark appears only in page headers. Labels outside the widget bodies identify sizes in the tour or the launcher picker.

The guided tour opens real dialogs in its same-origin app frame, and each page step sets the journal to that page. The native widgets are `AppWidgetProvider`/`RemoteViews` implementations (`JournalWidgetProvider.Small`, `.Essential`, `.Medium`, `.Large`) with offline vector drawables and immutable intents. **Widget layouts may only use `@RemoteView` classes** (`FrameLayout`, `LinearLayout`, `RelativeLayout`, `TextView`, `ImageView`, `ImageButton`, `ProgressBar`, …): a plain `<View>` spacer makes the launcher refuse the whole widget with "Can't load widget" / "Impossibile caricare il widget", which is why the Large widget's header spacers are empty `FrameLayout`s. Both target **today** even if the journal was browsing a historical date. Tapping opens a form; only Save writes an entry. Native nutrition is a derived private cache updated on edits/import, not a second journal. Missing days render zero. The system can defer periodic and midnight refreshes. Widget launcher behavior must be checked on the target device.

## Notifications

Settings > **Notifications** switches on local reminders. Everything is opt-in (all off by default), nothing leaves the device, and there is no push server. Nothing is stored beyond `settings.notifications` in `kcalsync_settings` (so it is part of the JSON backup).

| Reminder | What you choose | Tapping it opens |
| --- | --- | --- |
| **Water** | How often: every 30, 45 min, 1 h, 1 h 30, 2 h, 3 h or 4 h, between a *From* and an *Until* time (a window that ends before it starts crosses midnight; at most 48 a day). The three water messages rotate. | Add Water |
| **Meals** | One switch **and one time per meal**: Breakfast 08:00, Morning snack 10:30, Lunch 13:00, Afternoon snack 16:30, Dinner 20:00 (defaults; Extra has no fixed time). | Add Food |
| **Custom buttons** | One time (19:00). The text lists your custom buttons (first three, then …). Needs at least one custom button; skipped if you delete them all. | The custom-button dialog/picker |
| **Weight** | One time (07:30). | Log Weight |
| **Log your data** | One time (21:00): the general "don't forget to log your data" reminder. | Today |

How it works:

- `buildNotificationPlan()` (`src/utils/notifications.ts`) is a pure function: settings + language + meal and custom-button names → a list of daily alarms (`id`, hour, minute, title, body, target screen). IDs are stable: water `1000+`, meals `2000-2004`, custom `3001`, weight `3002`, log `3003`.
- **Android:** `@capacitor/local-notifications` (v8) schedules each alarm as a repeating *daily* system alarm (`schedule.on = {hour, minute, second: 0}`, `allowWhileIdle`), so reminders arrive with the app closed and are restored after a reboot by the plugin's boot receiver. Three notification channels (*Water reminders*, *Meal reminders*, *Other reminders*, named in the app language) let the user tune sound per type in Android's own settings. The status-bar icon is `drawable/ic_stat_kak.xml`. Android 13+ asks for the `POST_NOTIFICATIONS` permission the first time a reminder is switched on. On Android 12+ without the "alarms & reminders" special access the plugin falls back to inexact alarms, so a reminder may be delayed by a few minutes.
- **Browser:** the same plan runs on timers and the Web Notification API, so reminders only arrive **while the page is open** (the tour's embedded journal never schedules, only the top-level page does). A note in Settings says so.
- `useNotificationScheduler()` (`src/utils/useNotificationScheduler.ts`, used by `WidgetAppBridge` in `src/App.tsx`) re-syncs the system alarms 400 ms after any change to the settings, the language or the custom-button names, and routes a tap on a notification to the matching screen through the same `showScreen` bridge as the widgets.
- Settings shows a banner when notifications are blocked or unsupported, an *Allow notifications* button when permission is still pending, and **Send a test notification**.
- Old backups and stored settings without `notifications` load with the defaults (`normalizeNotificationSettings`).
- The guided tour has a **Notifications** step (after Settings, before the widgets): five tappable previews built from the app's real notification strings, beside the live journal with Settings > Notifications expanded.

## Journal workflows

- **Header:** every page starts with the profile button (left), the Kakcalculator wordmark (centre, which returns to Today) and the settings button (right), followed by the page tabs. The two round buttons are 44 px touch targets; the tab pill below them is deliberately low (32 px buttons in a 40 px pill) so the header stays short. Scrolling down collapses and hides the top app-name row (`48 px` scroll range) together with the full-width header background and border, as well as the pages indicator pill bar below it (`68 px` downward delta); scrolling back up smoothly reveals only the translucent floating page pill (`68 px` upward delta with `requestAnimationFrame` damping and smoothstep easing, without clipping the pill height or bringing back the header background), while the top app-name row and full header surface return when scrolling back to the top of the page.
- **Dialogs:** on phones every dialog opens as a sheet anchored to the bottom of the *visual* viewport (8 px above the edge or the gesture area), so it is as low as possible and rises with the keyboard instead of hiding behind it; on `sm` and wider screens it is centred. The Today quick-add dock uses 48–52 px buttons with 22 px icons. A popup hides the dock without remounting the page or replaying its entrance on dismissal.

- **Today:** day arrows/calendar, Intake/Burned and net balance, macros, optional sugar immediately to the right of salt, six meal slots, and collapsible activity, water, bowel and custom trackers. The Compact/Normal/Expanded switch sits centred under the macros; it and the open states are remembered. Settings controls the Today dock, not the fixed lists of widget shortcuts.
- **Food:** multilingual fuzzy search, favorites, remembered portions, multi-item queues, saved meals and previous-day copying. Search covers 410 bundled foods (curated products, generic foods and USDA entries, one entry per food: the estimated "fried / baked / grilled / boiled …" variants that used to be generated from every generic food were removed), your own records, and an offline catalogue of **130,000 Open Food Facts products**. Every result shows the weight that will be pre-filled (the last weight you logged for it, else its classic portion when the data has one, else 100 g/ml) with the carbs, protein, fat and kcal of exactly that weight; picking it opens the quantity screen with that same weight. Its main **Add another item** button queues the food and returns to the picker; saved meals and previous-day meals join the same batch instead of logging and closing the dialog. The journal is only written when you press **Log all**, which appears after the first item. New unknown barcode searches are the only automatic HTTP fetch made by a logging workflow, and only after the user requests a lookup.
- **Movement:** Walk/Run by distance or duration, Other with 181 local Compendium activities, or a saved custom activity. Records retain the estimated burn at logging time. Water, weight, bowel entries and custom quantities are independent daily measurements.
- **Custom:** saved meals, recipes, ingredient quantities, catalog, barcode lookup and manual creation. Meals/recipes support logging, editing, fuzzy search and confirmed deletion. Ingredient searches use the same catalogue, result rows and default weight as Add Food; adding an ingredient queues it and offers another by default, with **Save meal** appearing only after the first ingredient. The chosen ingredient shows its carbs, protein, fat, fibre and salt for the weight, and every listed ingredient shows its own macros and kcal. In Ultra Minimal, section and action labels are reduced while item names and values remain.
- **Statistics:** 7-day, 30-day or custom ranges, energy/nutrient averages (including sugar when enabled), custom tracker charts, weight trend, and a collapsible 7-day breakdown with a sugar total on each day. Ultra Minimal nutrient averages put `/day` beside the number; custom quantity charts use a bottom-right per-day label.
- **Period:** optional calendar, daily flow/mood/symptom/notes, pill schedule, intercourse log, cycle history and opt-in nutrition charts. Profile sex controls default visibility unless overridden. Existing data is not deleted when hiding the page. Estimates are not contraception or fertility guidance.
- **Day overview:** single-tap a date in Today's calendar, double-tap a date in Period, or inspect a day from Statistics. The order is energy, macros (if present), Poop (unless hidden), Activity, Weight/Water, then logged custom trackers. Icon backplates blend with their sections. The Open in Today footer stays available while scrolling.
- **Settings and Profile:** collapsible groups, each with its sub-sections titled when open. **Appearance**: English/Italian (above Appearance), app Theme (Light/Lite Dark/Dark), home-screen widget style (Light/Dark) immediately below Theme, Style presets (Classic plus 6 style themes and the Mono hue picker), and Ultra minimal mode. **Today & pages**: the Today quick-add buttons, **Track sugar intake**, hide poop fields and hide Period page, and the quick-add food shortcuts. **Custom buttons**: your custom trackers and the *Custom button in widgets* switch, which is disabled until at least one custom tracker exists (and is forced off when the last one is deleted). The quick-add buttons are stacked one per row. Widget style, the widget custom button, Ultra minimal mode and sugar tracking have labels without explanatory subtitles. Then pinned foods, the Foods database, and profile and JSON backup. In Ultra Minimal, salt is the supplied nested diamond with four spokes in Today, Statistics and Custom. Its accessible name still identifies salt.

## Motion

Motion follows the usual guidelines: it is quick, driven by physics, interruptible at any moment and uses only `transform`/`opacity`. `src/utils/spring.ts` samples a damped spring into a CSS `linear()` curve, published as `--ease-soft` (about 3 % overshoot, **271 ms**: pages, sheets, docks, values) and `--ease-bounce` (about 20 % overshoot, **297 ms**: pressed controls and the dock). Browsers without `linear()` get a cubic-bezier fallback. The same curves drive CSS, keyframes and Web Animations.

- **Press feedback:** a pressed button shrinks to 90 % in 90 ms, then springs back with a small overshoot (`.pressable`).
- **Page swipe** (`src/components/common/PageSwiper.tsx`): The full-width `<main>` listens for Pointer Events, including in its margins and empty bottom padding. Only a horizontal drag past 10 px takes pointer capture; buttons still receive ordinary taps. The two pages follow the finger together with physical drag resistance (`0.72×` initial damping). A deliberate distance (`27 %` of the viewport width, 86–116 px) or a fast flick (`> 0.65 px/ms` past `12 %` width) is required on release so short, slow drags snap back without changing the page, then a single transform settles in 80 to 150 ms. Vertical scrolling, pinch zoom, cancelled drags and horizontal lists retain their own behaviour.
- **Page handoff:** both pages move on one rail. Releasing a completed swipe promotes the already-mounted destination rather than replacing it with a second copy. The rail settles to its normal position with no persistent animation fill. A new press cancels the settle, ordinary taps keep their original target, the outgoing page cannot expose a second quick-add dock, and as soon as the finger releases (`kc-page-dragging` removed), the floating dock and its action buttons immediately animate in over 130 ms from the swipe direction (`--kc-swipe-dir`, appearing from the right when moving to a right page and from the left when moving to a left page).
- **Dialogs:** drag the handle or title bar down to dismiss; a short or cancelled drag returns the sheet to rest. While a sheet is open, scroll chaining and browser pull-to-refresh are disabled. Closing it releases the scroll lock, leaving the original page, its scroll position and its dock in place. The dialog body still scrolls above the keyboard.
- **Settings groups** open with a 300 ms height animation (`src/components/common/Collapsible.tsx`); switches and chevrons use the bounce spring.
- Values that change (intake, burned) and the Today day change use the soft spring (`src/utils/motion.ts`, `.anim-value`).
- All of it, including the [launch intro](#launch-intro), is disabled by `prefers-reduced-motion`.

## Launch intro

When the app opens it plays one of the **six one-phase launch animations** supplied in `src/assets/kakcalculator_intro/` (`animations/01..06-*.svg`, documented in `intro_animation.md`): Sketch & Plop, Tactile Keypress, Swirl & Unfold, Polarity Iris Flip, Flush Vortex Spin and Modular Coil Stack. Only phase 1 is used (1.06 to 1.28 s, ending exactly on the brand icon); the `-lockup` files and the phase-2 wordmark morph are not used.

- **A different animation every launch.** `pickIntroAnimation()` chooses at random but never the animation of the previous launch (remembered in `localStorage` key `kcalsync_intro_last`). The choice is made once per page load.
- **Over a live boot.** The journal mounts underneath the overlay, so nothing waits for the animation. The final frame (the icon) is held for 220 ms, then the overlay fades out over 240 ms. Tap anywhere to skip.
- **Theme-aware.** The SVG is inlined (so CSS variables resolve) and the overlay uses the app's `--bg`. In Light the cream/ink tokens are `#FBF3E3` / `#232325`; in Lite Dark and Dark the card takes the surface colour and only the cream strokes remain, as in section 5 of `intro_animation.md`.
- **Where it runs.** Android, `?view=app` and the browser tour's top-level page. It never runs inside the tour's iframes (the live journal and widget gallery), with `?tour=1`, or when `prefers-reduced-motion` is set.
- **URL switches (review only).** `?intro=0` skips it; `?intro=1` to `?intro=6` forces one animation, e.g. `index.html?view=app&intro=4`.

Files: `src/components/intro/introAnimations.ts` (the six imported SVGs with durations, the picker and `shouldShowIntro`), `IntroSplash.tsx` (overlay, timing, skip) and `intro.css` (overlay, tokens, fade). `App.tsx` renders `<IntroSplash />` next to the journal or tour.

## Startup

What the Android app does to open quickly: the HTML carries a tiny pre-paint script that applies the saved Lite Dark / Dark theme and background before any CSS or React runs (no light flash); fonts are declared in `src/index.css` as two latin-only woff2 faces instead of the fontsource stylesheets (−69 KB of inlined base64; other scripts fall back to the system font); `Intl` number/date formatters are created once per locale + options in `src/utils/formatters.ts` (`numberFormatter`, `dateFormatter`) instead of on every call, and the Today calendar computes its weekday labels only while it is open. The 12 MB food catalogue is not part of that bundle: it is fetched lazily (about 150 ms) the first time a food search opens, so it costs nothing at launch. The tour, widget gallery and demo data are tree-shaken out of the Android bundle by the `VITE_ANDROID_RELEASE` guard in `App.tsx`. Measured in headless Chromium with 4× CPU throttling (median of 5): first paint 304 → 272 ms, app ready 628 → 555 ms, first contentful paint 744 → 656 ms.

## Gestures and storage

Horizontal swipes on main content follow the finger and switch visible tabs, even on blank areas and ordinary fields (see [Motion](#motion)); animations are interrupted by the next touch. Text areas, contenteditable areas, sliders, open dialogs, horizontal scrollers that can still move in the swipe direction, and marked controls keep their gestures. The Statistics weight trend accepts swipes. Dialogs close by swiping their handle or title bar down. The outer 8 CSS pixels are reserved for system-edge navigation; multi-touch, canceled gestures and predominantly vertical movement do not navigate. On Android, Back dismisses the top dialog or Today calendar, returns from the catalog, then returns to Today. At the root, it backgrounds the app. The keyboard and launcher-level long-press/resize are handled by Android.

The source of truth is the journal in WebView `localStorage`. `kcalsync_day_logs`, `kcalsync_profile`, `kcalsync_custom_foods`, `kcalsync_used_foods` (catalogue foods you picked or starred, so favorites, recents and recipes keep resolving), `kcalsync_prebuilt_meals`, `kcalsync_custom_activities`, `kcalsync_settings` and `kf_period_data` hold the main records. Language, recent portions and UI expansion preferences have separate local keys. The Settings JSON backup includes profile, day logs, custom and picked catalogue foods, meals, activities, settings and cycle data; it does **not** include every UI preference. Android export uses the system document picker. Backups are unencrypted. Clearing storage or uninstalling can remove the journal.

Camera scanning is optional and depends on `BarcodeDetector` and permission. Known barcodes (your own foods and the 130,000 catalogue products) and manual food entry work offline. New Open Food Facts searches and opening external nutrition references need internet. Native widgets use no network. The browser service worker is not used by the APK.

## Calculations and colors

Food values are per 100 g/ml. Logged portions retain a nutrient snapshot. The journal and widget use the same calorie and macro functions. BMR uses Mifflin-St Jeor; total burned is BMR + activity + estimated thermogenesis. Net is intake minus expenditure. The water estimate uses the profile and activity. Estimates are not direct measurements.

Shared accents: intake/food green `#C9EFD3`, activity/burned red `#F6D0D0`, weight violet `#E2D6FF`, water/carbs blue `#CFE7FE`, protein/poop peach `#FAE0B4`, fat lavender `#E2D6FF`, and custom tracker lemon `#F7E9AA`. ## Data sources

### Activity sources

- [`src/data/activities.ts`](src/data/activities.ts) holds **181 activities** with MET values copied from the [2024 Adult Compendium of Physical Activities](https://pacompendium.com/) (Herrmann SD, Willis EA, Ainsworth BE, et al., *J Sport Health Sci* 2024;13(1):6-12, [doi:10.1016/j.jshs.2023.10.010](https://doi.org/10.1016/j.jshs.2023.10.010)). Each row keeps its Compendium **specific-activity code** (e.g. `17200` = walking 3.5–3.9 mph, 4.8 MET), English and Italian names and a category. Every code and MET value was cross-checked against the official category tables.
- The 2024 edition changed many values compared with the 2011 edition used by most calculators (e.g. running 6.0–6.3 mph is now **9.3** MET instead of 9.8, 7 mph is 11.0, brisk walking 3.5–3.9 mph is 4.8). Values here follow 2024.
- **Adding an activity:** append a row `[code, id, category, met, name_en, name_it]` to `ACTIVITY_ROWS`. The `id` is saved in logs and favourites, so never rename an existing one.
- MET values are population averages for adults and a good estimate, not a measurement; individual cost varies with fitness, terrain, technique and conditions.

### Nutrition sources

- **84 new reference entries** come from the [USDA FoodData Central SR Legacy release (April 2018)](https://fdc.nal.usda.gov/download-datasets/), including whole-milk and part-skim ricotta, legumes, grains, snacks, and prepared dishes. Each new entry links to its source. Carbohydrates follow the dataset's carbohydrate-by-difference value (including fiber); salt is calculated as sodium × 2.5, converted from mg to g.
- The [Bakkerij Van Hecke rice pie](https://bakkersonline.be/be-nl/vanhecke-ferrerlaan/product/92214/rijsttaart) uses the bakery's per-100-g product label. Values are specific to that product, not a universal estimate for homemade rice pie.
- The source-backed data is bundled with the app and is separate from the original catalog (whose generated "boiled / grilled / oven-baked / pan-fried …" variants were removed; the USDA entries that carry a cooking method in their name are real source data and stay). To regenerate the USDA selection, download the [official SR Legacy CSV zip](https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_sr_legacy_food_csv_2018-04.zip) and run `python3 scripts/generate-usda-foods.py <path-to-zip>`.

### Open Food Facts catalogue

**Browse the full database:** Custom > Foods > Browse Foods opens the same offline index as Add Food. Its count includes matching catalogue and local foods without counting remembered barcodes twice. Name, brand, barcode and category searches cover the whole file, not just the current page. Pages contain at most 36 decoded food records from the combined results. Favourites and custom foods retain their own filters. If the file fails to load, the browser identifies the partial list and offers a retry. Restore `public/data/off-foods.bin` from Git if it is missing. The Android source ZIP includes this file for rebuilding as well as the copy synced into the APK.

`public/data/off-foods.bin` (12.3 MB, 130,000 products) is the offline product catalogue. It is built from the [Open Food Facts](https://world.openfoodfacts.org) CSV export (about 3.2 million of its 4.9 million products have a complete nutrition table) by `scripts/build-off-catalog.mjs`, run with `npm run build:catalog`.

- **Kept:** a name, a barcode and a complete, self-consistent per-100 g/ml table (energy, fat, carbohydrates, protein; the energy must agree with the macros within a generous tolerance, alcohol included). **Ranked:** Italian market first, then popularity and completeness. The best 130,000 are written (all of them are Italian-market products), after removing duplicates (same name, brand and energy).
- **Saved per product:** name, brand, barcode, kcal, carbs, **sugar**, fat, protein, fibre, salt, g or ml, category, and the **classic portion** (Open Food Facts `serving_quantity`) when the record has one: 128,697 products have sugar and 25,758 have a classic portion. Missing values are stored as unknown, never invented.
- **Sugar** is stored in `FoodItem.sugar` and snapshotted on every logged item. **Settings > Today & pages > Track sugar intake** adds it to Today beside salt, food search and quantity screens, custom-food creation, barcode results, saved meals/recipes, day overviews, Statistics averages and the daily breakdown. Products without a sugar value show `—` in food details; daily totals sum the available values. The 410 bundled foods have no sugar value.
- **Format "KOFF" v1**, chosen for speed: little-endian, every section 8-byte aligned, so the browser wraps the downloaded buffer in typed arrays with no parsing or copying (barcodes as `Float64Array`, nutrients as scaled `Uint16Array`, string offsets as `Uint32Array`). Names and brands are UTF-8 blobs decoded only for the rows a search returns; one ASCII blob (`" word word\n"` per product) is the search index. The layout is documented at the top of the script and read by `src/data/offCatalog.ts`.
- **Search:** word-prefix match over name and brand, every word must match, whole-phrase and leading-word hits first, popularity order inside a group. A search takes about 50 ms on 130,000 products. Hits are ranked on the same scale as the bundled fuzzy search (above their typo matches, below an exact word) and mixed into the same list. Products you pick or star are copied into `kcalsync_used_foods` so they stay resolvable by id.
- **Rebuild:** `npm run build:catalog` streams the 1.5 GB export from `static.openfoodfacts.org` (nothing is stored; about 1 GB of RAM is enough; around two minutes), or `node scripts/build-off-catalog.mjs <export.csv.gz> --limit 130000 --out public/data/off-foods.bin` for a local file. Afterwards bump `DATA_CACHE` in `public/offline-worker.js`, then `npm run android:prepare`.
- **Licence:** data © Open Food Facts contributors, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/); notice in `public/licenses/OpenFoodFacts.txt`. The records are crowd-sourced and can be wrong.

## Project provenance

The Android shell, launcher assets, package ID and Gradle configuration were restored from [`MatMon28/Kakcalculator`, commit `81368cc`](https://github.com/MatMon28/Kakcalculator/tree/81368cc). The current web source was retained, not replaced with the older upstream UI. The missing wrapper JAR was restored from the pinned Capacitor template and checked against Gradle's published SHA-256. No Next.js wrapper, Postgres/Drizzle database, Firebase setup or remote server is part of this build.

Leftovers of that earlier Next.js scaffold (`next.config.ts`, `drizzle.config.json`, `eslint.config.mjs`, `src/app/`, `src/db/`, the unused `src/components/common/Toast.tsx`) are inert: nothing in `src/main.tsx` imports them and Vite does not bundle them, but they are the only files that make `npx tsc --noEmit` report errors. The stale `postcss.config.mjs` was removed because Vite auto-loaded it and it required `@tailwindcss/postcss`, which is not a dependency; Tailwind runs through `@tailwindcss/vite` in `vite.config.ts`.
